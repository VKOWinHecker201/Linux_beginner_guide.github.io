# First Things First: What Actually Is "Linux"?

Strictly speaking, Linux is the kernel—the core program that sits between your physical hardware (CPU, RAM, NVMe drive, GPU) and your applications. On its own, a kernel cannot give you a file manager, a web browser, or even a shell prompt.

To create a complete operating system—called a Linux Distribution (Distro)—maintainers bundle the Linux kernel with standard command-line utilities (typically GNU coreutils), a C library (glibc or musl), an init system to boot services, a package manager to install software, a display server (Wayland or Xorg), and a Desktop Environment. Because every piece is modular, different distros can feel drastically different while running the exact same Linux kernel underneath.

[CRITICAL SAFETY NOTE] Why does `rm` have no Recycle Bin?

Unlike deleting a file in a graphical file manager (which moves it to ~/.local/share/Trash), running rm unlinks the file directly from the filesystem. Always be cautious with sudo rm -rf (recursive + force). While modern GNU rm includes built-in protection (--preserve-root) that blocks accidental sudo rm -rf / unless explicitly overridden, running rm -rf ~/ * (with an accidental space after the tilde) will immediately wipe your entire home directory. Module 03 // Graphical Shells & Window Management

A Guide to Linux Desktop Environments

On Windows or macOS, the graphical interface is permanently welded to the operating system. On Linux, the graphical desktop is just a replaceable suite of user-space programs.

Full Suite

What is a Desktop Environment (DE)?

A Desktop Environment is a complete, cohesive bundle that includes a Window Manager / Compositor plus a taskbar/panel, system settings app, file manager, lock screen, power manager, Bluetooth/Wi-Fi applets, and notification daemon. Examples: KDE Plasma, GNOME, XFCE, Cinnamon, COSMIC, MATE, Budgie.

Minimalist / DIY

What is a Standalone Window Manager (WM)?

A standalone Window Manager (or Wayland Compositor) only controls how application windows are placed and drawn on screen. It does not ship with a settings app, file manager, or status bar—you assemble your own using tools like waybar, rofi, and dunst. Popular tiling WMs include i3wm (X11), Sway (Wayland), and Hyprland (Wayland).

What About Tiling Window Managers (i3, Sway, Hyprland)?

Module 04 // Linux Graphics Stack & Display Protocols

Introduction to Wayland and X.Org (X11)

Whenever you move your mouse, type on your keyboard, or watch a window animate across your monitor, a Display Server Protocol coordinates those pixels and inputs. Here is why Linux is completing a once-in-40-years transition from X.Org (X11) to Wayland.

feh — assets/x11-vs-wayland-pipeline.svg [1120x420] DRM/KMS • libinput • XWayland
WHY REPLACE X11?

The 1984 Design Debt

X11 was designed at MIT in 1984 so mainframes could draw primitive 2D rectangles over a network to dumb terminals. Because early X11 had no concept of modern GPU compositing, modern desktops had to bolt on an external Compositor. Worse, X11 has zero client isolation: any running X11 application can query the global keyboard state (XQueryKeymap) or capture your entire screen silently.

HOW WAYLAND WORKS

Protocol, Not a Single Binary

Wayland is a lightweight communication protocol. Instead of running a separate X Server and Window Manager, your Desktop Environment's compositor (KWin on KDE, Mutter on GNOME, wlroots on Sway) is the display server. Applications render their own window buffers via Vulkan/OpenGL and hand the GPU memory handle (DMA-BUF) directly to the compositor.

BACKWARD COMPATIBILITY

XWayland & Portals

What happens if you run an older X11 game or Steam app on Wayland? XWayland automatically launches a tiny, rootless X11 server inside your Wayland session so legacy apps run seamlessly. And for legitimate screen recording (like OBS Studio or Discord screen sharing), Wayland uses XDG Desktop Portals + PipeWire so you explicitly approve which window or monitor an app can see.

Module 05 // The Upstream Root Distributions

Comparison: Debian vs. Fedora vs. Arch Linux

Although hundreds of Linux distributions exist, roughly 90% of desktop and server distros trace their ancestry back to one of three upstream foundations: Debian, Fedora (Red Hat), or Arch Linux.

feh — assets/linux-upstream-family-tree.svg [1100x340] Lineage & Derivative Map

Debian

"The Universal OS"

Founded by Ian Murdock in 1993, Debian is 100% community-governed (no corporate owner) and strictly adheres to the Debian Free Software Guidelines (DFSG). Since Debian 12 ("Bookworm"), official installer ISOs include non-free hardware firmware by default so Wi-Fi cards work out of the box.

The 3 Debian Branches:
• Stable: Released every ~2 years. Packages are frozen; only security & critical bug fixes backported.
• Testing: Staging ground for the next Stable release.
• Unstable ("Sid"): Rolling development branch where new packages land first.
Ideal For: Production servers, home labs, and desktop users who want an OS that never changes its behavior for years.

Fedora Linux

"The Innovator"

Sponsored by Red Hat and governed by the Fedora Project Council, Fedora serves as the upstream innovation ground for Red Hat Enterprise Linux (RHEL). It follows four foundations: Freedom, Friends, Features, First.

Why Developers Love It:
• Semi-Rolling Feel: Point releases every 6 months, plus continuous Linux kernel updates (e.g., 6.11 → 6.12 → 6.13) within the same release.
• Modern Plumbing: Ships with Btrfs filesystem, zram swap, SELinux mandatory access control, PipeWire, and fast dnf5.
Ideal For: Workstation users, laptop owners, gamers, and software engineers who want modern packages without manual system assembly.

Arch Linux

"DIY Rolling Release"

Created by Judd Vinet in 2002, Arch is an independent Rolling Release distribution: you install it once and run sudo pacman -Syu to stay continuously on the latest stable upstream software forever.

Core Pillars of Arch:
• Minimal Base (plus `archinstall`): Boots to a CLI ISO where you pick your exact partitioning, bootloader, audio server, and DE (or use the guided archinstall TUI script).
• The AUR (Arch User Repository): Community repository of PKGBUILD scripts allowing you to build virtually any Linux software in existence.
• The Arch Wiki: The most comprehensive documentation resource in all of Linux.
Ideal For: Enthusiasts and tinkerers who want to understand every service running on their machine and always have bleeding-edge software.

Gentoo Linux & Void Linux: Should a Beginner Use Them?

Difficulty: Enthusiast / SysAdmin

Gentoo Linux

Founded 2000 (Daniel Robbins) • Package Manager: Portage (emerge)
Source-Based Meta-Distro

In binary distributions (like Ubuntu, Fedora, or Arch), maintainers compile source code on their servers so everyone downloads the exact same pre-built binary package. Gentoo Linux is a source-based distribution: by default, its package manager (Portage, invoked via emerge) downloads raw source code tariffs and compiles them locally on your CPU using your exact compiler optimizations (CFLAGS="-march=native -O2").

Key Gentoo Technologies (Accurate Modern Facts):
  • USE Flags (/etc/portage/make.conf): Declarative keywords that tell Portage which optional features to compile into or strip out of software across your entire system. Don't own a printer or Bluetooth adapter? Set USE="-cups -bluetooth" and no program on your PC will ever compile code or pull dependencies for printing or Bluetooth.
  • Init Freedom: Gentoo officially supports both OpenRC (its traditional dependency-based init system) and systemd via official Stage 3 tarballs.
  • Official Binary Packages (`binhost` since late 2023): You no longer have to spend 4 hours compiling web browsers! Gentoo now hosts official GPG-signed binary packages (`emerge --getbinpkg` / `-g`) so users can install pre-compiled binaries for huge packages like Firefox, Chromium, Rust, or LLVM while compiling everything else from source.

Void Linux

Founded 2008 (Juan Romero Pardines) • Pkg: XBPS • Init: runit
Independent Rolling

Void Linux is a completely independent, general-purpose rolling-release distribution created from scratch by a former NetBSD developer. Unlike Ubuntu or Manjaro, Void is not a fork of Debian, Fedora, or Arch. It prioritizes BSD-like simplicity, speed, and clean engineering.

Key Void Linux Technologies (Accurate Modern Facts):
  • runit Init System: Instead of the monolithic systemd suite, Void uses runit—a tiny, lightning-fast UNIX init scheme with automatic process supervision. Enabling a background service on Void is literally just creating a symlink: ln -s /etc/sv/NetworkManager /var/service/.
  • XBPS (X Binary Package System): Written from scratch in C, xbps-install -Su is among the fastest binary package managers in existence, paired with xbps-src for building packages in clean chroots.
  • First-Class glibc and musl Editions: Users can download official ISOs compiled against either standard GNU C Library (glibc) or the lightweight, standards-strict musl libc. (Historical accuracy note: Void transitioned back from LibreSSL to OpenSSL in March 2021 for upstream compatibility.)

The Honest Engineering Verdict

Should a Beginner Use Gentoo or Void Linux as Their First OS?

Short Answer: No—not on bare metal as your first Linux installation.

There is a vocal internet subculture that tells newcomers to "jump straight into Gentoo or Arch to learn the hard way." In reality, trying to use Gentoo or Void on your primary computer before you know how Linux filesystems, permissions, init services, and package managers work usually leads to frustration—like booting into a black TTY screen with no Wi-Fi because you didn't install wpa_supplicant or symlink dbus.

Why Gentoo Is Hard on Day 1:

Gentoo has no graphical installer. Following the Gentoo Handbook requires partitioning your NVMe drive in the CLI with fdisk, formatting filesystems, extracting a stage3 tarball, mounting /proc and /sys, chrooting, writing /etc/fstab, configuring and compiling a Linux kernel (or using gentoo-kernel-bin), and configuring GRUB—all before you even have a graphical desktop.

Why Void Is Better Saved for Month 2+:

Void actually includes a straightforward TUI installer (`void-installer`) and installs in 5 minutes! However, because it uses runit instead of systemd, 90% of beginner copy-paste tutorials online (which assume sudo systemctl enable --now ...) will not work verbatim, and audio (PipeWire/WirePlumber) or Polkit session setup requires reading the Void Handbook carefully.
